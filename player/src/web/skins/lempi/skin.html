    Straight away cuts whatever is playing here, the way a skip does, so you hear at once whether it worked — and from then on any drift is corrected continuously, by dropping or repeating single frames, which is inaudible. At the next track disturbs nothing now, but that track may be minutes off and alignment is then only corrected at each track change, half a second at a time.

    Either way, being exactly in step needs both players' clocks disciplined by chrony against the same server. A node on systemd-timesyncd will be corrected towards its own clock error instead.

    write cue sheets

    A whole-side capture holds one set of tags, so a guest such as MPD names every track inside it after the file — about a third of this library. Ticking this writes a .cue file beside each capture, which guests read to get the real titles. This writes files into your music folder, which nothing else in Lempi does; it is why the choice is yours and the default is off. Existing sheets Lempi did not write are left alone, and unticking leaves written ones in place.

    Needs a restart. The sheets are written the moment you tick, but Lempi reads which passages have a cue track only when it starts and hands that list to the guest — so titles keep coming out wrong until you use Restart Lempi below. MPD also needs a database update before it can see the new files at all.

    write cover images

    A capture has no art of its own, so a guest shows whatever it finds for the artist — one cover on every album. Ticking this writes cover.jpg beside each capture that is alone in its folder, using the art Lempi already holds. A capture sharing a folder with others is skipped: one folder has room for one cover, and giving several albums the same picture is the problem rather than the fix. This writes files into your music folder. A folder that already has a cover is never touched, whoever put it there.

    No restart needed: a guest reads the folder when it is asked for a picture. A client that has already cached the wrong one may need its own refresh.

    write into its cache

    A lyrics file beside a capture would hold every song in it at once, so per-song words go where a client keys them by artist and title — its own cache. Ticking this writes one file per song Lempi has words for. This writes into another application’s data folder, and it only helps a client running on this machine: a phone in another room keeps its own cache and will not see these. A file already there is never replaced.

    Lempi needs no restart. The client may: Cantata showed these only after it was restarted, since it reads its cache as it draws a track.

    write into the music folder

    The companion to the setting above, and the one that reaches a client on another machine — provided that client can read your music folder, since it builds this path from its own Music Folder setting. This writes files into your music folder. Captures are deliberately skipped: a client tries this file before the cache, so one written beside a capture would replace each song’s own words with all twelve at once. A file already there is never replaced.

    Lempi needs no restart. A client reads these beside the audio as it plays a track, so it may need to move off the track and back before it notices one.
