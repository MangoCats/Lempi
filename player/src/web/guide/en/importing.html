Importing & Refining Music

Lempi itself only ever plays a library — building and curating one is Vipunen's job, a separate program with its own browser console. This tier walks through getting new music in, correcting how it's identified, adjusting exactly where a track starts and ends, and what "flavor" analysis actually is. If you're starting completely from nothing, see Starting From Nothing instead — this tier assumes a library already exists and you're adding to or refining it.

Opening Vipunen's console

Vipunen's console is its own local web page, run alongside Lempi, pointed at the same library file and (optionally) the folder(s) your music actually lives in. Once it's running, open it in a browser the same way you open Lempi's own page. It never changes your library directly — every action that writes anything runs as a tracked, watchable job instead, so nothing happens invisibly.

On a desktop where Vipunen is installed, Lempi's own Browse page has a launch Vipunen link right next to "review ids" — click it and Lempi starts Vipunen's console for you, pointed at the same library you're already browsing, and opens it in a new tab once it's ready. The link only appears where it can actually work; on the Raspberry Pi appliance, or on a desktop without Vipunen set up, it stays hidden rather than leading anywhere dead.

Adding a folder of music

  1. On the Jobs page, type in the folder you want to add and click propose. This is a rehearsal — nothing is written yet — and shows you what it found: how many files, how many would actually be added, how many are already in the library, and which steps it will and won't run (see below).
  2. Review the proposal, then click confirm → induct to actually run it for real.
  3. Once it finishes, use the "after an induct" button to tell a running Lempi to notice the new music — otherwise it won't be selectable until Lempi is restarted.

Underneath, that one "induct" step is really four in order:

  1. Ingest — reads each file's tags and length, and files it into the library as a plain, unidentified track.
  2. Extract — analyzes the actual audio to work out its "flavor" (see below).
  3. Identify — fingerprints the audio and checks it against MusicBrainz to work out exactly which recording it is.
  4. Merge — folds any identification results in.

A plain folder of ordinary song files doesn't need anything more than that. A few things are deliberately not attempted automatically, because they need information a folder scan can't infer on its own: splitting a single whole-album capture into separate tracks, fetching cover art or release details (both need a confirmed identity first), and measuring exact fade-in/fade-out points. Each is its own action, covered below or in Advanced Features.

The Library and Folder pages

The Library page is Vipunen's overview: counts of tracks, how many are missing a MusicBrainz identity, how many have never been checked, how many have no flavor data yet — plus a searchable table of every track. Click a title to open its full profile page (see below). The Folder page compares what's actually on disk in your music folder(s) against what the library thinks is there — a quick, unverified pass (by path, size, and modified time, not by actually re-reading the audio) that's useful for noticing files the library doesn't know about yet, or rows whose file has gone missing or moved.

Confirming or correcting an identity

Sometimes the automatic fingerprint match is wrong, or there wasn't enough to go on. From a track's profile page in Vipunen, "Review in Lempi" opens Lempi's own Review page for that track (Vipunen hands you off to it, launching Lempi if it isn't already running). There you'll see what the library currently believes next to what the audio fingerprint actually suggests, each candidate with a match-confidence score. A Play now button sends it straight to the player so you can judge by ear. You can also search MusicBrainz directly by song or album name for tracks the fingerprint match can't reach at all (self-released music, an unusual remaster). Decide with Use the match, Keep ours, or Decide later; a separate box lets you fix just the artist credit.

A review decision is a draft until it's applied — Vipunen's profile page will show a banner reminding you a decision is waiting to be folded in, with the exact command to run. This two-step design exists because changing what a track is also has to correctly carry over its play history.

Adjusting where a track starts, ends, and fades

"Edit boundaries in Lempi," also from a track's profile page, opens a waveform editor. Six markers on the waveform — start, end (blue), lead-in/lead-out (amber — timing for when a smooth handoff with the next track is allowed), and fade-in/fade-out (violet — an actual volume ramp, independent of that handoff) — can be dragged directly, or set precisely with the numeric fields beside the waveform if dragging isn't accurate enough. A separate field sets the track's overall volume (gain). Play the edit to check it, then Save edit — like a review decision, this is also a draft until a separate apply step folds it into the library.

Flavor analysis

"Flavor" is a large set of measurements (71 numbers) describing what a recording actually sounds like — mood, genre character, danceability, and more — computed once per track from the audio itself. This is what the Program Director uses to keep a program feeling consistent and to blend one song into the next smoothly (see the Appendix). It is a fully real, working, already-applied part of the library today, not experimental — essentially every track has it. Its honest limit: even the reference data it's built to reproduce doesn't perfectly agree with itself between two different recordings of the exact same performance, so treat flavor as a strong signal for "does this fit," not an exact science. A track's own flavor values are visible in full on its Vipunen profile page.

Splitting a whole-album capture into tracks

If a whole CD was captured as one long file, it needs to be split into individual tracks before each one can be played, tuned, and identified on its own. This is a real, working feature, but it's early and still being validated — treat results as a good starting point, always worth a listen through the boundaries it finds. It works by being told roughly how long each track should be (or the exact expected lengths, if you have them), and searches the audio for the actual silences or track breaks near those points.

Ripping a CD directly

Lempi can bring in a physical CD, but it doesn't operate the drive itself — you rip the disc first with separate ripping software (on Windows, Exact Audio Copy is the supported route today; the equivalent Linux path isn't reliable yet), then point the ingest tool at the folder that rip produced. Given the disc's own table of contents, track boundaries are exact — no guesswork like the whole-album case above — and if the disc is recognized, Vipunen pulls its real track titles and artist credits directly rather than relying on a fingerprint match per track. This is a real, working feature for a single disc at a time; box sets and hidden bonus tracks aren't handled yet.
